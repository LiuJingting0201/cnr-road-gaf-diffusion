# Taxi reproduction debugging protocol
Primary target: the four published Porto Table 5 metrics, without any architecture change, endpoint replacement or post-generation snapping. Also compare with a locally matched Porto 10k fit and equal-size request cohorts. All four metrics, both seeds and physical distance must be reported. Numerical similarity to the historical Porto table on another city cannot establish exact reproduction. In particular, a fixture that has near-perfect real/real hotspot F1 or a high real/real OD JS should not be treated as equivalent to matching Porto.

Development sequence, fixed before new training outcomes:
1. Independently audit all raw identities and journeys, projection/units, interpolation, distance and times, conditional-field ranges, train support and grid coding. Verify primary metric definitions against the paper/release and cited implementation.
2. The original time header mixed episode number into departure time. Refit the same 10k records using actual simulation time at departure. Preserve all other fields, seed, batch 220, fixed AdamW and final epoch 200. Score old and corrected models on all 1000 previously assigned development requests with identical sampling noise. Record real matching start/end cells, median error and resolution sensitivity.
3. Compare with two new local Porto fits on a fixed random subset of 10k long observed trips and 1000 existing reserve trips. Match SUMO's training protocol, compute and sampling protocol exactly. Use training-only transforms, plot/sample count and physical quantities. This contrasts datasets and exposes the effect of spatial support, not a causal test of a single domain variable.
4. Refit with the 20k nested corrected taxi data if the 10k fits do not reach published spatial or length results or the paired endpoint task remains materially worse. Use 200 epochs and batch 440 to keep 9200 updates; report that gradient batch and data exposure change. Compare on the same development requests. Preserve common SUMO-10k scoring bounds/bins across the two sizes for the diagnostic.
5. Freeze the 20k arm for deployment if both seeds improve development joint OD JS against corrected 10k without worsening length W1 on either seed; otherwise freeze corrected 10k. Evaluate the frozen pair once on 1000 fresh mixed-traffic SUMO taxi journeys, and compare against independent observed cohorts at matching N and measurement settings. Do not continue adjusting evaluation grid or fitting additional modules to match the paper's decimal values.

Control for world size: the prior historical 10k used two GPUs per seed. Run an additional old-clock fit on one GPU per seed with otherwise identical code and ordering to the repaired 10k fits. This permits isolating the clock change apart from RNG grouping. Fit this control on development only. After selecting the frozen SUMO model, report whether its two fresh results fall within the 10th–90th percentile range of 50 equal-N Porto resamples per metric; treat this as a diagnostic of practical agreement, not formal statistical equivalence. Never use the fresh set to tune the pipeline.

Published point estimates are reported directly rather than given a retrospectively chosen tolerance. For the matched 10k Porto control the primary table uses the two actual 1000-request scores. The additional Porto 10th–90th percentile reference in step 5 is the already archived long-cohort experiment (50 subsets of the saved 3000 draws, trained on 46,470), not a confidence interval for the authors' scores. SUMO fresh test scores are compared under the originally specified grid before optional city-core diagnostics. Refit versus fixed-weight diagnostics and development versus fresh results are labelled separately.
