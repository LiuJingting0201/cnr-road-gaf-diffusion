# DiffTraj source and scoring audit

The primary numerical reference is the NeurIPS 2023 paper, Table 5, Porto: density 0.0087, trip 0.0132, length 0.0242, pattern 0.847. Section 5.2 samples 3,000 trajectories per method for its main benchmark. Appendix C.1 does not identify the precise Porto evaluation population, bounds, histogram edges, hotspot count, sample identities or aggregation. Results of SUMO training concern transfer of the method to simulated Monaco taxis. [NeurIPS paper, §§5.1–5.2 and Appendices B–C](https://proceedings.neurips.cc/paper_files/paper/2023/file/cd9b4a28fb9eebe0430c3312a4898a41-Paper-Conference.pdf)

## Preprocessing and training

| Component | Primary-source evidence | SUMO implementation and consequence |
|---|---|---|
| Tracking and sampling | Appendix B.1 removes trajectories shorter than 120 positions for the two-city setup. The release interpolates linearly along sample index to 200 positions and restores requested original point count. Appendix C.1 provides no independent Porto filtering receipt. | The SUMO collector uses 1-second native positions, full departure-to-arrival events, at least 120 positions and episode-disjoint sets. This threshold corresponds to at least 119 s, versus 1,785 s for a 15-second Porto record. Compare duration, native count, real length and interpolation error before attributing differences to training. |
| Coordinates and units | The official notebook rescales its coordinate channels to Chengdu longitude/latitude. The author advises z-scoring coordinates and continuous request attributes. | SUMO x/y are projected metres on the MoST grid. The local pack retains centimetre-precision deltas, integrates Euclidean distance in metres before interpolation, and fits transformation parameters on training records. |
| Header information | The eight columns encode departure time, total distance, duration, original point count, average interpoint displacement, average speed, start cell, end cell. Departure index is a 5-minute time-of-day category. The author confirms cumulative distance, duration in seconds, original point count, distance/duration speed and z-scores only for the five continuous columns. A separate reply describes map-matched distances for the source attributes. | The SUMO runner computes these from native events independently of the generated track. Start/end IDs are two categorical columns. The original 10k pack **artificially added the episode seed modulo 1,440 minutes to departure seconds**. Simulation demand has no associated real time-of-day. Episode numbers encode the split: 10k train time IDs 208–240, development 192–197, reserved 176–181; all 2,000 evaluation headers therefore contain a time embedding never seen during training. Measured by reading the prepared 10k arrays. Use locally elapsed simulation time from the real episode start for all partitions or generate physically meaningful, independent demand periods. Fit transformations on training observations and document synthetic clocks. |
| Request-grid resolution | The author used both 12×12 and 16×16 grids and suggests computing coordinate extrema to obtain bounds. That reply addresses origin and destination **conditions**. The evaluation appendix specifies 16×16 cells. | The local embedding IDs use 16×16. Coordinates are mapped to 0–255 consistently, and the release feeds these integers directly to separate origin/destination tables. Published city-specific evaluation boundaries remain unresolved. |
| Training and sampling | The release defaults to 200 epochs, batch 1,024, learning rate 0.0002, AdamW, coordinate-noise MSE, 500 linear noise levels, guidance 3, and saves ordinary network weights. The released notebook uses 100 DDIM transitions with eta zero and does not call eval(), so dropout remains active. | SUMO uses the released coordinate architecture, fixed AdamW and epoch-200 ordinary weights, but global batch 220 to give 9,200 updates on 10k trips; eval-mode dropout disabled and inference batch 32. The Porto comparison fits used 46,470 trips, clipping, cosine decay and validation-selected weights. Matching update counts alone leaves multiple differences. |

## Metrics and what the OD calculation means

- Density. The paper compares occupancy of real and generated points; its authors' posted JS function adds a pseudocount of 0.000001 to each raw count, then computes natural-log JS divergence. The local primary score is natural-log JS without the pseudocount. The smoothing sensitivity changes density JS by less than 0.000000001 and joint OD JS by less than 0.00004 in the 10k taxi fits. [Author's heatmap scoring code](https://github.com/Yasoz/DiffTraj/issues/15#issuecomment-2249691574), [seed 42](../taxi10k/42/sumo-final.json), [seed 43](../taxi10k/43/sumo-final.json).
- OD. DiffTraj describes preserving the association of start/end cells. Its cited methodological source, LDPTrace, constructs a vector indexed by ordered (origin cell, destination cell), increments it once per trip, then discards the marginal histograms and computes JS on the joint vector. This supports the local joint OD calculation. Neither the author reply in issue 15 nor the released DiffTraj files seen here disclose the actual Table 5 OD counting code. Separate origin and destination distributions are informative auxiliary diagnostics. A 256×256 joint histogram need not be densely populated: actual support, concentration, sample size, and errors in assigning the specified OD jointly matter. [Original metric definition, Appendix B.2](https://arxiv.org/html/2304.11582#A2.SS2), [cited predecessor's joint count](https://github.com/yuntaod/LDPTrace/blob/2d30e4135db11fd50d1fb98f59a1e84ebc61b218/LDPTrace/code/main.py#L278-L294), [joint score actually used](https://github.com/yuntaod/LDPTrace/blob/2d30e4135db11fd50d1fb98f59a1e84ebc61b218/LDPTrace/code/main.py#L405-L413).
- Length. The paper measures accumulated segment distance, but omits the Porto histogram edges. Our primary 20 bins use training quantiles. LDPTrace uses 20 equal-width buckets with a different edge convention. Changing bins to match the published scalar after seeing it would invalidate the comparison. [LDPTrace length code](https://github.com/yuntaod/LDPTrace/blob/2d30e4135db11fd50d1fb98f59a1e84ebc61b218/LDPTrace/code/experiment.py#L183-L208).
- Pattern. DiffTraj describes frequent individual cells and top-n overlap F1; n is unspecified. LDPTrace mines contiguous sequences of 2–8 cells and uses frequent sequence sets. It cannot supply DiffTraj's missing n by analogy. Local single-draw top-20 F1 changes in increments of .05. Compare fixed n and bounds across our conditions, record tie policy, give observed-reference variability and use the published scalar as context. [DiffTraj B.2](https://arxiv.org/html/2304.11582#A2.SS2), [LDPTrace pattern code](https://github.com/yuntaod/LDPTrace/blob/2d30e4135db11fd50d1fb98f59a1e84ebc61b218/LDPTrace/code/experiment.py#L211-L242).

The authors describe random trajectory selection, recommend considering a lower point cutoff for scarce data, and suggest a data scale around 100,000 as a practical example. Exact Porto rows, seeds, and grid edges were not specified in those answers. The statement about data scale is not an established minimum.
