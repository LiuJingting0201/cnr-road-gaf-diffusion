# Per-trip origin and destination checks

Each row of [per-trip.csv](per-trip.csv) compares one stored, unmodified draw with the observed endpoints for its own request. Both seeds use the same 1,000 requests in the same order within each city. The cities do not share requests. SUMO uses the 10,000-trip corrected-clock model and development observations. Porto uses the 10,000-trip long-journey model and reserved observations.

- `city`, `seed`, `draw_index` identify a saved model output. The zero-based `draw_index` follows the original sampling order. `pack_index` is the row number in the reproduction input pack.
- `origin_error_m` and `destination_error_m` are the distances between the generated and originally observed coordinates per request. SUMO uses projected distances in metres. Porto uses great-circle distances on longitude and latitude (Earth radius 6,371 km). The model receives origin and destination cell identifiers. Metre discrepancies express proximity to one observed realization within those conditions.
- The three `*_hit` columns give 0/1 membership of the generated endpoints in the requested cells. These use the exact 16 by 16 training grid for each city and clip overflow to the grid edge as in the existing four-metric scorer. Two additional columns flag whether each endpoint lies within training bounds before clipping. The JSON supplies both original and strict-in-bounds hit counts. The original four distribution scores are recomputed using saved draws restored to each trajectory's native count and checked against their archived model scores.
- [summary.json](summary.json) gives per-seed medians, the 90th and 95th percentiles, counts of trips with both ends within selected physical radii, cell hits, the number of discrepancies between the requested and observed endpoint cells, and ordered request and reference hashes.
