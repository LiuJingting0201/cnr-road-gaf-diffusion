# 原Hilbert/GAF承接关系（当前优先级）

用户已确认：仓库不包含组内CNN分类器；分类目标是交通参与者类别。允许重训CNN，但必须承接原构图。现阶段暂停新增guidance与增广实验，先核对原表示与真实分类任务；轨迹合成仍为最终目标。

## 可核验原来源

原仓库所有9个远端分支与完整27个可达提交已获取（包括本地2次审计提交）。此前副本是只跟踪main的浅克隆，不能把此前的搜索称为全历史审计。原编码文件从dev提交4773ad65到week07没有变化。

vendor/original_cnr按原字节保存5个模块，PROVENANCE.json记录来源、提交与每文件SHA256。没有把位移GAF称为原Hilbert编码。

原链：全局坐标min/max→逐时刻Hilbert标量（eps=.0037）→每车辆squeeze、mirror duplicate至224→pyts GASF/GADF（sample_range=[0,1]）和8-bin uniform MTF→三个通道分别按本批次极值映射0–255并round→RGB uint8。

Hilbert没有重排时间点，它是逐点空间标量映射。squeeze按重复段缩减；短序列镜像重复，可能形成反向时间片段；无足够重复的长序列可能无法压到224，代码会明确拒绝而不是悄悄换成插值。原函数没有按时间显式排序；本次canonical数据按时间排序。

另一个脚本build_no_speed_paired_dataset.py采用先插值到224、理论固定通道范围；它是后续重建数据分支，不等于上述原模块。之前的Hilbert表示实验使用64/224连续窗口、新CNN及固定通道范围，不能拿其分类分数代替原全车辆流程的结果。

## 本次对齐与明确适配

直接调用原Hilbert和序列处理函数；小样本整体流程须与原encode_trajectory_frame逐元素一致。RGB仍为GASF/GADF/MTF，不换成dx/dy四通道。归一化和通道极值只用训练车辆估计，推理冻结，计数超范围裁剪，避免每次待预测批次改变图像。该训练/部署适配与原批次范围策略分别记录。

使用midimost的class2作为六类标签，沿用已有车辆级划分。x/y是SUMO局部坐标，填入原归一化坐标位置，不声称GPS。先每车辆全轨迹构图，测试集不编码、不评价。CNN明确为新训练的三通道分类基线，不声称复现未知组内网络结构或精度。

## 对guidance的限制

原Hilbert递归分区、squeeze及uint8取整都是离散操作，不能直接通过原构图向坐标反传梯度。先确认分类器在原表示上的有效性，再检验它对生成任务的时间尺度是否适用：全车辆轨迹与64点短窗不等价。

若分类有效，优先研究保持原编码的评分/重采样引导（在拓扑合法候选中使用原CNN评分），并明确区分采样内引导与生成后筛选。可微代理或soft-Hilbert只能作为额外改造，必须验证与原CNN的一致性，不能冒充原方法。当前不启动这些guidance实验。
