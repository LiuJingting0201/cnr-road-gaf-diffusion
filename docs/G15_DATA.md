# G15 mixed traffic — design locked before production
Aim for 80,000 different SUMO participant IDs in balanced fixed-length delivery: exactly 8,000 train, 1,000 validation and 1,000 reserved per class (total 10,000 each). Labels: pedestrian (SUMO person walking), bus, motorcycle, private_car, bycicle (source spelling), taxi_or_uber (SUMO taxi), truck and delivery (SUMO delivery vehicle). Use the same Monaco MoST map and SUMO 1.28.0. Every eligible observation was emitted by SUMO. Do not use diffusion sampling to fill deficits.

Disjoint seed ranges for each split; no previous G10–G14 seeds. Independent random reachable OD, departure time and demand per episode; street reuse is expected. One randomly located 512-point continuous window per participant. Every point must have an FCD road identifier, finite coordinates and a 0.25 s interval. Net displacement >5m. Report attempted, rejected, eligible, delivered, unique OD pairs; identify exact duplicate coordinate sequences across all splits and never deliver duplicates. Use deterministic ordering, equal quotas, no replication. This estimates a balanced experimental population rather than city mode shares. Walking, taxi and bus are simulated using SUMO defaults, without timetables or real ride requests. New labels require an extended model and new training. Native FCD qualification is separate from E3 map reconstruction. G14 provides the strictly reconstructed five-class dataset. New holdout is reserved for future use; do not evaluate models here.

Production simulation uses 100 requested participants per class/episode, departure in simulation seconds 0–100; FCD starts at 80 s and simulation ends at 310 s. Motor-vehicle ODs use SUMO-permitted directed paths of 2.5–9 km; for people, OD separation is 350–1,200 m and SUMO picks the actual walking path. A 20-per-class pilot confirmed all eight categories. In the initial production round, the pedestrian router rejected some OD pairs across disconnected sidewalks. Those run logs were retained. The runner removes only the identified unreachable pedestrian, reruns the same demand and records the rejection. No vehicle type is substituted and no guessed crossing is inserted. Discontinuous windows with any position jump >1.25 m per tick for pedestrians or 15 m for vehicles are excluded. This is a simulator-native road-reference and continuity check, not the E3 projection audit.

The split seed ranges begin at 262001 (train), 263001 (validation) and 264001 (holdout). The exporter ranks eligible IDs by SHA256 of a fixed prefix and participant ID, removes repeated coordinate sequences quantized to the exported centimetres, and takes the fixed class quota. The archive includes train.csv, validation.csv, holdout.csv and a per-episode manifest. Split unit is a full simulator episode, not a row. Distinct OD counts measure one aspect of coverage; shared streets and repeated origin/destination pairs are allowed.

## Run
In an isolated worktree with the SUMO 1.28.0 G10 environment, use `SUMO_HOME=$(realpath g10-env/sumo) PYTHONPATH=g10-env:src OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python scripts/g15_queue.py`. The finite queue resumes complete episodes and writes failure or completion receipts. Preserve the initial failure log before retrying. Final CSVs are read back in full and verified for counts, ID continuity and fixed time step. The network SHA256, per-episode demand hashes, exclusion counts and package digest are recorded. Raw coordinates are distributed in the local dataset archive, outside Git.
